# Test projects

Read [`docs/test-harness.md`](../docs/test-harness.md) before writing or debugging any Yaat.Sim test; the root `CLAUDE.md` Testing rules (TDD, real navdata, timeouts, the MTP runner CLI) still apply here. These are the gotchas specific to the test projects:

- **Static singleton races**: xUnit runs test classes in parallel by default. Tests that read static singletons populated by `TestVnasData.EnsureInitialized()` — `NavigationDatabase`, `AircraftProfileDatabase`, `AircraftSiblingMap`, `AirlineFleetData`, etc. — can race when one class is mid-initialization while another reads the singleton.

  **Symptom**: a test passes in isolation but fails intermittently when run alongside profile-loading classes; the failure shows mismatched values where both should come from the same lookup (e.g., `Expected 98 / Actual 96.5` because `DecelRate` returned the default-fallback in one call and the loaded profile in the next).

  **Fix**: call `TestVnasData.EnsureInitialized()` in the racing test class's constructor so the lookup is pinned to a stable state before any test method body runs. Never assume singletons are empty — another test class is always one tick away from populating them.
- **Use the real aircraft tables, never a replacement**: the aircraft tables `TestVnasData.EnsureAircraftDataInitialized` loads (`WakeTurbulenceData`'s CWT table among them) load once per process and are process-wide, so a test that installs a small table of its own breaks every later reader in the run, and `EnsureInitialized()` (navdata only) does not restore it. Pick a real aircraft type whose real data gives the case under test. A case real data cannot express installs its fake set through a scope that restores the previous table on dispose (`using IDisposable … = X.ScopedOverride(…)`, as `NavigationDatabase.ScopedOverride` does), never a bare `Initialize`. No yaat-server test installs a bare aircraft table: `AircraftTableIsolationTests` fails if any source file in that project calls a process-wide aircraft-table writer (`WakeTurbulenceData.Initialize(`, `AircraftProfileDatabase.Initialize(`, `AircraftPerformance.SetProfileCorrectionAdapter(`, `AircraftCategorization.Initialize(`, `AircraftSiblingMap.Initialize(`, `FaaAircraftDatabase.Initialize(`, `FaaAircraftDatabase.ApplyOverrides(`), and checks the real categories survive the classes that read the table.

  A client test that places an overlay at a fraction of a server-planned leg moves with the type's real FAA dimensions, so pick the position from the real-data geometry (`GroundViewModelApproachLegOverlayTests` covers only run-in fractions 0.7 and 0.75 for this reason; earlier on the run-in the overlay re-plans from the taxi-start node, YAAT-196).

  A local pass does not prove a test is order-independent: the class order differs between runs and between machines (CI included), and a `<Assembly>.uniqueid` file next to the assembly did not pin it in practice. To prove a fix, write a test that installs the offending table first and then makes the assertion, or repeat the filtered run many times.
- **A recording test picks its ground layout**: one whose archive bundles an airport layout builds its engine's ground data with `RecordingGroundData.Evergreen(why)` (behaviour that must keep holding on today's airport) or `RecordingGroundData.VersionPinned(archivePath, why)` (behaviour that only makes sense on the airport as recorded), `why` naming the reason. `RecordingArchiveLayoutGuardTests` fails a file that does neither. See [test-harness.md](../docs/test-harness.md).
- **Per-user paths via `YaatPaths`**: Every `%LOCALAPPDATA%/yaat` path routes through `YaatPaths.AppDataRoot` / `YaatPaths.Combine(...)` (in `Yaat.Sim`), never raw `Environment.GetFolderPath`. Test projects that touch `UserPreferences`, `AppLog`, `MainViewModel`, or any per-user cache must set `YAAT_APPDATA_DIR` to a unique temp path in a `ModuleInitializer` (pattern: `tests/Yaat.Client.UI.Tests/ModuleInit.cs`) so tests don't mutate the developer's real `preferences.json`.
- **`xunit.runner.json` must be Content-copied**: `tests/Yaat.Client.UI.Tests/xunit.runner.json` sets `parallelizeTestCollections: false`; without a csproj Content include copying it to `bin/`, xUnit silently parallelizes and races `UserPreferences` on the shared `preferences.json`. Diagnose an `Expected [...] / Actual []` failure by confirming that copy exists before suspecting `UserPreferences.Save`.
- **A UI test that asserts `StatusText` (or a tool message built from it) awaits `vm.NavDataInitialization` first**: the startup nav-data load writes `StatusText` in the background. Rule and reason in [test-harness.md](../docs/test-harness.md) "Avalonia headless UI tests".
- **UI tests share one `preferences.json` per process, and class order varies between runs** (even with a fixed `.uniqueid`), so a leaked preference shows up as a random flake in a later class. A test that flips a pop-out flag (`IsTerminalPoppedOut`, `SetPoppedOut`) uses `PreferencesFileScope` **and** resets the flag in memory before teardown, because `WindowGeometryHelper.FlushAllSavedGeometries` writes every live window's preferences back.

  A test that drives a command input docks the terminal itself rather than inherit the pop-out state from the file. Never `main.Close()` in a test: it latches `AppLifetime.IsShuttingDown`, after which every pop-out's chrome close counts as an app shutdown; tear down with `MainWindowHost.CloseAll`.
- **"Access to the path is denied" on a replacing move is not a test race**: on C: an antivirus scan holds a just-written file open for a few milliseconds (measured: ~1 in 10 back-to-back write-then-replace moves denied under `%TEMP%` and `%LOCALAPPDATA%`, none on D:). Whole-file saves go through `AtomicFile.WriteAllText`, which retries the move; a new writer that calls `File.Move(..., overwrite: true)` directly brings the failure back.

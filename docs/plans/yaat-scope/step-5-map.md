# YAAT-2224 (Scope step 5): findings and proposed split

## 0. The answer in six lines

1. The Scope has no click-action machinery yet: `ScopeFieldAction` has one member, `None` (`src/Yaat.Client/Views/Scope/TrackPresentation.cs:124-128`), and every presenter field passes `None` (`TrackPresenter.cs:533,607,648,669,773-779`). Canvas events are only `AircraftLeftClicked`, `AircraftRightClicked`, `AircraftDwellLockToggleRequested` (`ScopeCanvas.cs:250-259`); `OnPointerPressed` ignores every button but left and right (`ScopeCanvas.cs:424-455`). Middle-click does nothing today (the highlight is drawn, `ScopeRenderer.cs:244`, but nothing in `Views/Scope` writes it).
2. Today's `SendCommandAsync` cannot take Scope text: it reads `CommandText` and clears it (`MainViewModel.cs:2943-3233`). The only text entry is `SubmitCommandTextAsync`, which types into the main box (`MainViewModel.cs:2914-2932`). A Scope preview area that leaves "YAAT's main command line" alone needs that body extracted to a text-parameter method first. That extraction is the foundation of part 5a.
3. Scope entries in the ERAM dialect have no client path at all. CRC's wire handlers parse and validate them in yaat-server (`../yaat-server/src/Yaat.Server/Hubs/CrcClientState.Eram*.cs`), then record a `RecordedEramEntry` applied by `src/Yaat.Sim/Commands/EramEntryEngine.cs:74-109` (verbs TRACK FREEZE COAST QQ QR QS LF VCI LEADER HANDOFF PO POACK POCLEAR POCONVERT DRI DWELL MIN FDB CO HM QH DM). No hub method lets an RPO submit one (`ServerConnection.cs` InvokeAsync list: none). The STARS dialect largely maps to existing YAAT canonical "Track Operations"/"Data Operations" verbs (`CommandRegistry.cs:1274,1334-1383,1817-1860`).
4. Measure exists only for Radar and Ground: `RblView { Radar, Ground }` (`Views/Map/RangeBearingLines.cs:27-31`), shared 15-slot store (`RangeBearingLineStore`, `:74-79`), shared state `MainViewModel.Measure` (`MainViewModel.cs:134-137,1973-1976`); `.rbl` hardcodes the Radar view and Radar track lookup (`MainViewModel.cs:2893-2896`). Ctrl+M arms the shared tool from `WindowHotkeys.cs:130-137` but the Scope canvas never reads `IsMeasuring`, so an armed tool plus a Scope click just selects.
5. CRR and speed-to-time have no YAAT implementation on the client. The server holds CRR groups as engine state (`src/Yaat.Sim/Simulation/Eram/EramCrrGroup.cs:10`, `RecordedEramCrrGroup`, membership on `AircraftEramState.CrrGroupLabel`) but `rg Crr` over `src/` outside `Yaat.Sim` finds nothing, so the client never receives groups or labels. Speed-to-time is ERAM `LC` (docs/crc/eram.md:528-532) with no code anywhere.
6. The decision for the "CRC alias" question: `Yaat.Client.Core` `CrcAlias*` is CRC's `.aliases` text-expansion file reader (dot verbs → text, echo, URL, scope-marker actions: `MainViewModel.CrcAliases.cs:77-129`), reached only for dot-text or `CRC ` prefix (`MainViewModel.cs:2990-3022`). It is NOT a scope-entry grammar and is reusable only for dot entries.

## 1. Field menus (part 1 of the ask)

### What a "field" is
`ScopeFieldSlot` (`ScopeFieldSlot.cs:7-110`) is the field vocabulary; each template places a subset (`ScopeTemplates.cs`):
- STARS (`ScopeTemplates.cs:100-117,120`): L1 Callsign (+VfrMark, StudentLevelMark); L2 Altitude, GroundSpeed, CwtType, Ident; then Squawk, StatusLine3 (owner/handoff/point-out/scratchpads), Atpa, ModeC, NoLandingClearance, ConflictAlert, InstructorNote. Limited = Squawk, Altitude, Ident.
- ERAM (`:154-179`): L1 Callsign (= CRC Field A); L2 EramAltitude (Fields B+C+char 4 in ONE slot), AltitudeMismatch, GroundSpeed, CwtType, Atpa, Ident; L3 StatusLine3 (= Field E status) + HsfIndicator; L4 Line4Notes; Column0 Vci (row 2), NotYourControl (row 3). There is no Field D (CID) slot and no separate Field E speed slot.
- EuroScope (`:196-216`): Owner, Callsign, TypeCwt, Destination, Ident, Altitude, AssignedAltitude, AssignedSpeed, AssignedHeading, AssignedRunway, Scratchpad1, Scratchpad2, Handoff, plus Squawk/ModeC/warnings/InstructorNote. This is the template whose flyouts "become the field menus" (plan README:44).
- Mixed is a per-track router to STARS or ERAM (`ScopeOwnerKind.Resolve`).

Hit-testing already returns the field: `ScopeFrame.FieldAt(x, y)` (used at `ScopeCanvas.cs:461-464`); the rects are the same ones drawn (plan README:56).

## 7. OPEN DECISIONS (neither docs nor code settle; recommendation each)
D1. Sink for responses. Options: Scope-local feedback only; also echo to `StatusText`/terminal. Recommend: Scope feedback for Scope-originated entries, keep terminal history (`AddHistory`) so the record exists; `StatusText` only for main-box input.
D2. "Click sends": the plan says plain click sends. A click on a field opens a menu (CRC); the plain/Shift distinction can only apply to a menu row. Recommend: field click opens the menu (and selects the aircraft); a plain row click sends; Shift+row-click stages. Field A keeps the dwell lock toggle (ERAM) and selects.
D3. Where Shift+click stages. Recommend: pilot picks stage into the MAIN command line (plan README:40 says "the command line", and the Favorites precedent `MainViewModel.Favorites.cs:306-311`); scope-data picks stage into the Scope preview area (so they run in the right dialect). Say both in USER_GUIDE.
D4. Middle-click on STARS-template blocks: highlight toggle (CRC) vs execute. Recommend: preview non-empty → execute (every template); preview empty → template's own middle action (STARS highlight; ERAM Field A QF). Mixed uses the block's own kind.
D5. Dialect detection and the `QQ`/`QZ` collision. Recommend: when the first token is a dialect verb of the profile's kind (STARS or ERAM, from `MainViewModel.ScopeProfile`), read as scope entry and say so; `PILOT` prefix or a leading `.` forces pilot/dot; Mixed profile: use the selected track's owner kind (`ScopeOwnerKind.Resolve`), else ERAM. Do not remove the `QQ`/`QZ` aliases from the registry; the preview line states "ERAM QQ (interim altitude)" vs "PILOT TEMPALT".
D6. Key capture: printable keys go to the preview only when the canvas has focus; Esc: clear preview first, then disarm tools; Ctrl+Shift+T stays TDM (owner ruling, YAAT-2387; CRC uses Ctrl+T, which YAAT keeps for Take Control); Ctrl+R recalls last (CRC) not YAAT's recall; F1 conflicts: plan "F1 hold codes" vs ERAM F1=QF: recommend keep the plan (held F1 shows beacon codes) and not implement function-key prefixes in 5a (board shows F3/F4/F5/F7: defer to a later issue).
D7. EuroScope tag on the Scope: heading mode (`RadarCanvas.EnterHeadingMode`) is canvas-bound. Recommend a Scope-side heading menu (rows from `RadarSpeedFlyout`-style builder: 5° steps) rather than porting the elastic-vector mode; the elastic vector is a parity item for step 7.
D8. Measure view: new `RblView.Scope` with its own lines (lines render only where placed, as for Ground) vs lines visible on the Radar and Scope alike. Recommend `RblView.Scope`; slot pool stays shared (15) so `.rbl 3` stays unambiguous; `.rbl` follows the focused surface (add an `ActiveMeasureView` on `MainViewModel`).
D8b. CRR state: client-local vs server-recorded. Recommend server-recorded (groups and `LF` are already engine state, recorded, snapshotted and CRC-visible; a client-local list would diverge from what the student sees). Needs the DTO.
D9. Speed-to-time semantics: readout only vs also stage a speed command. Recommend readout in feedback + Shift-stage row "SPEED nnn" in the speed menu; compute from ground speed to the fix at the sim clock; label as an estimate; aviation-sim-expert review (wind/TAS/CAS).
D10. Scope of STARS dialect in 5g: implement the verbs that map to existing YAAT verbs (track, drop, handoff, scratchpad, temp/requested altitude, leader, PTL, TPA) and answer "NOT SUPPORTED" for the rest (CRDA, consolidation, lists, coordination), as the plan "Reviews owed" scope-entry vs pilot split asks.
D11. ERAM transport: new hub method vs a new recorded canonical verb through `SendCommandAsync`. Recommend a hub method keyed by the instructor's active position (viewer = `AS` position, plan README:36) feeding the SAME handler body CRC uses, recorded as `RecordedEramEntry` (replay-safe). Measured: no existing path; unmeasured: how much of the `CrcClientState.Eram*.cs` validation is separable from the wire message.
D12. Dot entries (`.scope`, `.view`, `.rbl`, CRC alias verbs) in the preview: recommend yes, same `TryHandle*` chain, echoing into the feedback area (plan README:58).

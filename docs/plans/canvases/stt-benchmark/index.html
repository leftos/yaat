YAAT-1604: where the in-app STT benchmark lives in Settings > Speech

"Benchmark this machine" runs each installed model in each mode on each available device, one child process per run, on about 12 short committed clips. Each run records load + warm-up time, p50 and p90 latency per clip, peak RAM (working set) and peak VRAM. The results sit beside the reference WER and callsign recall from the committed stt-reference.json, which were measured on the CI natives and not on this machine, so they are the same on CPU and GPU. Picking a row applies its model, mode and device. A device change needs a restart. The cards' "Measured" row shows the result for the chosen mode and device.

The example machine has rasr-parakeet v2 fp32 and int8 downloaded, Whisper not downloaded, and the GPU runtime installed on a supported card, so the run set is 8: each rasr model × Accurate/Fast × CPU/GPU, in that order. The current settings are fp32 · Accurate · CPU. The row picked to apply in the done frames is fp32 · Accurate · GPU. The failing row in the "one row failed" frames is int8 · Accurate · CPU. The lanes draw only the part of the Speech section that changes, in the look of the approved lane C mock (docs/plans/canvases/stt-speech-settings/index.html). A dashed yellow outline marks the benchmark's own controls.

Each lane shows five states: never run, running, done, one row failed, and no GPU runtime. Each lane takes one approach to the GPU rows when the runtime is missing, and says which.

A. The table inline in Settings > Speech, under the model picker, with the button above it

A "Benchmark" group sits between the model picker and the Mode row. The button and the run status come first, and the results table under them stays in the section. "Use selected row" sets the model picker and the Mode and Device radios, and Settings' own OK or Apply saves them, as with any other change in the window. The cards' Measured row fills in as well. No GPU runtime: GPU rows are left out, with one line saying why.

Shared by every lane, and what this mock assumes

  • Columns: Load is load + warm-up; p50 and p90 are per-clip latency in ms; RAM is the run's peak working set; VRAM its peak GPU memory, "—" on the CPU. The two columns on blue come from stt-reference.json, measured once per model and mode on the CI natives, so a CPU row and its GPU row show the same WER and callsign recall.
  • The Whisper row is listed for its reference figures but not run, because Whisper is not downloaded on the example machine. With Whisper downloaded it adds Fast-only rows (Whisper has no Accurate mode).
  • "current" marks the row that matches today's saved model, mode and device. A failed row, a greyed GPU row and the Whisper row cannot be picked.
  • "Use selected row" (lanes A and B) only sets the picker and the Mode and Device radios, and Settings' OK or Apply saves them, as for any setting in that window. It is not called "Apply" there, since Settings already has an Apply button. Lane C's window saves on its own Apply.
  • The failure text is the child process's exit code. "details in yaat-client.log" assumes the runner logs the child's stderr there.
  • "About 2 minutes" is a guess from 8 runs × (load + 12 clips).

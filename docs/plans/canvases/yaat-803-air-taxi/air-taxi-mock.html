Air taxi for helicopters: three open choices

Today no quick-command situation lists ATXI, so a helicopter on a pad gets the fixed-wing ground strip: Push back, Preset taxi route, Draw taxi route, Push back to, Check release window. Each artboard asks one open question as lanes A, B (and C), each with how it works and its worst case in use; no lane is marked as recommended.

Data is real: N812HL, an EC35 (the type COMMANDS.md uses for a helicopter spawn), at parking HELI1 on KOAK's north field, from the bundled oak.geojson. KOAK's layout has three helicopter positions, all parking features (HELI1, HELI2, HELI), 165 other parking positions and 16 spots. Runway holding positions are the RunwayHoldShort nodes LayoutInspector builds for each runway (--runway … --airport-code KOAK), each named by its taxiway, ordered from the threshold; a bar within 300 ft of the far threshold is left out, as Taxi to runway does. Distances are straight-line from HELI1, rounded to 50 ft, measured for this mock; the air-taxi path is not measured. Click rows, chips and tabs to see what each sends.

Row templates follow the quick-command mocks (docs/plans/canvases/quick-command-flyouts/, quick-command-taxi-to-runway-tabs/) and MenuGlyphRow.cs: Inter text, commands in JetBrains Mono at 70%, 22 px glyphs at stroke 1.9 in the ground colour, the Fluent dark menu surface, strip cells 40 px with the corner notch on a flyout cell, the 480 px cap of MenuCommandRow.InlineRowMaxWidth, tabs as FlyoutTabStrip draws them. The Air taxi glyph (rotor, body, skids, arrow) is a placeholder drawn for this mock, not a designed glyph. The page loads no web fonts, so it draws in Segoe UI and Consolas where Inter and JetBrains Mono are not installed. The outlined new-cell ring, the struck-through list entries and the dashed notes are mock annotations, not app UI.

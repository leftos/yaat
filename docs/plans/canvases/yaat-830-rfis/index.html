Report field in sight: which glyph

Report field in sight (RFIS) asks the pilot to report the airport in sight; under YAAT-830 the X3 approach flyouts grey their visual-approach (CVA) rows until the pilot has. It already sits fourth in the Approach situation's strip, between Assign speed and Cleared to land, with the glyph drawn in lane A. Lane A keeps that glyph; lanes B to E are four alternatives. No lane is marked as recommended.

Every candidate is drawn in the Tower family's amber (#FFC062), the colour the other Report commands (traffic in sight, N-mile final, at fix) already use, as QuickCommandStrip draws a glyph: a 24 px stroke path, stroke 1.9, round caps and joins, 32 px in a 40 px strip button, 22 px inline. None uses an eye (Cleared visual's) or a crosshair (Report traffic in sight's), and each lane draws its candidate beside both. The app runs dark only, so the app surfaces stay dark whichever theme this page is in.

Data: AAL204, a B738 on approach to KOAK runway 30, as the approach-ifr menu golden draws it (strip: Cleared approach, Maintain altitude, Assign speed, Report field in sight, Cleared to land; the two pickers carry the corner notch). Cleared visual is not in that strip: its button shows only while a visual clearance is offered. The pointer is drawn on the Report field in sight button, so the header's state line names it, as QuickCommandLabelLine does. Neighbour glyphs are copied from QuickCommandGlyphs.cs; every candidate's path data is in the README beside this page. The page loads no web fonts, so it draws in Segoe UI and Consolas where Inter and JetBrains Mono are not installed.

YAAT-2454: the SCOPE DATA column of the ERAM fourth-line menus. One popup, or one per token?

An ERAM full data block's fourth line is one field showing the HSF data (heading, speed, free text) set with QS: free text when set (LOWALT), else heading then speed (H270 S250); with none set it falls back to type or destination (B738). A ↴ at the end of line 2 marks that HSF data exists. Today a click on line 4 does nothing. YAAT-2454 makes it open the same two-column popup the altitude field got (YAAT-2442, lane B): SCOPE DATA rows that run QS entries beside PILOT rows that send pilot commands. The question is how many popups line 4 opens: one for the whole line, or one per token, as CRC's menus split it.

CRC (docs/crc/eram.md): the Heading Menu opens on "Field D (CID) or the fourth line assigned heading", the Speed Menu on "Field E (ground speed) or the fourth line assigned speed", and the Free Form Text Box Menu on "free form text in the fourth line", with "The Free Form Text Box Menu cannot be opened if the aircraft does not have any assigned fourth line free form text." Its Delete FDB Fourth Line pick "clears the aircraft's fourth line data", which is QS * UAL238.

Same rule in both lanes, as approved for altitude: a click on a row sends it (pilot) or runs its ERAM entry at once, with ACCEPT or the refusal in the feedback area; a Shift+click stages it in the preview area (QS H300 UAL238 bare, or PILOT UAL238 FH 300). Each row's faded monospace text is its exact entry for UAL238; ⵔ is the clear-weather symbol, typed with the ` key.

Lane A: One fourth-line popup

A click anywhere on line 4 opens one popup. SCOPE DATA stacks three sections, Heading, Speed and Free text, each a box and its rows; PILOT stacks Fly heading over Assign speed.

One hit region, whatever line 4 shows, so it always opens. Every HSF entry is one click away, free text included. The popup is tall, about 600 px, and the PILOT side holds two of today's flyouts at once.

Line 4 gets a click region per token: H270 opens Heading, S250 opens Speed, and the whole line when it shows free text opens Free text. Each popup is one SCOPE DATA section beside its matching PILOT panel. The dashed outlines mark the regions (not drawn in the app).

Matches CRC's split (Heading / Speed / Free Form Text Box menus) and keeps each popup small. Free text can't be started from a heading/speed line; a heading-only or speed-only line has one region; the fallback needs its own rule (B4).

What is real and what is approximated
  • Real, from the code: the entry texts are ScopeDataEntries (QS {heading} FLID, QS /{speed} FLID, QS */ FLID, QS /* FLID, QS * FLID, QS `{text} FLID); the stored forms H300, 20L, S250, 250-, M78, PS and free text of 1 to 8 characters with no spaces are EramEntryEngine.ParseHsfHeading / ParseHsfSpeed / ApplyQsFreeText. The line 4 text follows EramLine4. The PILOT commands (FPH, FH/TL/TR, LT/RT chips, RNS, RFAS, SPD 250, MACH .78) and the heading box placeholder and readout are today's HeadingFlyout and SpeedFlyout.
  • Approximated: the Fly heading and Assign speed panels are simplified (rose, chip sizes and glyphs drawn by eye; the knots and Mach chip ranges are plausible, not MenuCatalog.SpeedValues output). The styling, window, block and panel chrome are copied from the YAAT-2442 altitude mock (lane B). The app's UI font is Inter, drawn here in Segoe UI.
  • Not decided by this mock: whether the boxes open empty or holding the current value (here Heading and Speed open empty and Free text opens holding its text, as CRC's text box menu does); greying the Clear rows when nothing is set; whether the HSF indicator ↴ click (QS UAL238, toggle) changes.

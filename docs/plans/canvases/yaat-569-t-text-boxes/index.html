Squawk, Say and Scratchpad flyouts

Family T is the three free-text input popups left on the aircraft menu once families F and E are converted: Squawk… (SQ {code}, the only one checked today), Ask pilot to say › Custom… (SAY {text}) and Data Block › Scratchpad… (SP {text}). Converting them leaves Custom taxi… as the one caller of IMenuHost.ShowInputPopup.

The page draws one artboard per decision, each option a lane: the box form on the Squawk flyout, the squawk code check, Say › Custom, the Scratchpad seed and what ShowInputPopup keeps. Rows, chips and boxes are live; the line under each lane says what a click or Enter sends. Three page switches answer the smaller decisions the code forces (6, 7 and 9).

Commands, refusals and the parser's rules are read from the source. The aircraft, their codes, scratchpads and the recent Say texts are illustrative.

Carried from rulings and earlier parts (drawn as given, not as lanes)

  • Siblings are absorbed (owner ruling, YAAT-1018). The Squawk flyout carries the whole Squawk group (Squawk assigned code, random, VFR, normal, standby, Ident) beside the code box; the Say flyout carries the six Say queries beside Custom. No Squawk or Ask pilot submenu is left.
  • CTO Custom is an inline box row (family F, decision 4): always open, its fixed CTO prefix drawn as part of the box. A blank CTO box sends CTO (decision 5). Decision 1 here asks whether family T follows it.
  • Boxes are checked before sending; rows the sim would refuse are hidden, not greyed (family E). Here that hides Squawk assigned code when no code is assigned, as it already is (AircraftCommandApplicability.HasAssignedBeaconCode).
  • A one-box flyout is already built: Data Block's Temporary altitude… and Cruise… (AltitudeBoxPanel, AltitudeFlyout.cs:826-904): a title line naming the present value, one box row whose command column shows what Enter sends, or the refusal in red; Enter in the empty box closes, sending nothing. The Scratchpad flyout is drawn as its sibling.
  • Custom taxi… keeps its input popup (owner ruling), so ShowInputPopup survives with that one caller (MenuCatalog.cs:1192-1210).

Found while drawing (static reads, not run)

  • The Squawk box is stricter than the sim. FormatSquawkCode takes exactly four digits 0-7 (MenuCatalog.cs:1059-1060); the sim takes one to four octal digits up to 7777 (CommandParser.cs:4038-4067), so SQ 123 typed in the command bar sets 0123 but 123 in the box is refused. The box sends SQ {int.Parse}: 0347 goes out as SQ 347, which the sim reads as the same code.
  • A bare SQ is Squawk assigned code. SQ with no code is SquawkResetCommand (CommandParser.cs:4040-4043), the row the flyout already carries when a code is assigned (decision 9).
  • A bare SAY is not a SAY. The parser's only SAY arm takes an argument (CommandParser.cs:1078); a bare SAY falls to UnsupportedCommand (:1138) and the sim answers “Command not yet supported: SAY” (CommandDispatcher.cs:1509-1510). A blank Custom box can only send nothing (decision 8). The text goes out as typed, case kept; SP upper-cases (CommandParser.cs:1054).
  • SP is a toggle. Entering the scratchpad's present value again restores the previous one (TrackEngine.cs:415-421); a blank SP clears it, and clearing a cleared scratchpad restores the previous one (:405-413). A box seeded with the present value sends exactly that toggle on an unchanged Enter (decision 3).
  • The scratchpad limit lives on the server. Three characters, four where the facility allows it (ScratchpadRuleEngine.cs:16); a longer entry is refused “FORMAT”, the value unchanged (TrackEngine.cs:423-427). The room's limit reaches the client nowhere (yaat-server RoomEngine.cs:2341 reads it; no DTO carries it), and IMenuAircraft has no scratchpad member though AircraftModel holds Scratchpad1 (AircraftModel.cs:1513), so seeding or checking it needs a menu-side field (decisions 3 and 6).
  • The input popup's Clear button closes it. Clear and Escape both close without sending (MenuPopups.cs:122-125); nothing clears the text. The popup Custom taxi… keeps has the same button.

YAAT-1026 · context-menu quick commands · mock for the owner's decisions

All Commands reorganized, quick commands as text, a verb on every row

Owner goal (YAAT-1026, verbatim): “Also the goal is for the context menu to still offer All Commands and have all the commands under it, just better organized than before, and with the contextually appropriate ones surfaces (same as the icons, but with text, for those that prefer it). Each command should also list the command alias (so like "Taxi to... `TAXI`) so that it educates mouse users to the actual commands”

Owner ruling (verbatim): “Oh and add a setting that defaults to "show quick command icons", that when turned off, removes all the quick command icons, and instead the all commands menu subitems are added to the root of the context menu, for those that just hate the icons”

Each artboard below is one numbered decision, its lanes side by side, the recommended lane first. Two aircraft throughout: N123AB, a C172 VFR arrival on left downwind for 28L at KOAK, and UAL123, a B738 IFR departure taxiing at KSFO. Every lane draws the other decisions at their recommended answer, so a lane shows only the one thing it asks. The pointer arrow marks where the right-click landed; a submenu opens beside the highlighted row.

Settled elsewhere, drawn as given

  • YAAT-1018 lands first on feat/context-menu-flyouts, so this menu is drawn after it: Report when…, Squawk and Ask pilot to say… are flyouts carrying their whole group; every “(other)…” companion is gone; Cleared visual is a row inside the Cleared approach flyout, not an entry of its own; Join STAR is a tabbed STAR flyout.
  • YAAT-1028's strip (its own mock, docs/plans/canvases/quick-command-strip-categories/): no cap, icons grouped by task (Runway, Taxi, Vectors, Approach, Pattern, Pilot reports, Track and coordination), each group under a small label, six per row, release icons in their category, and categories whose icons add up to six or fewer share one row with a vertical separator. Its packing and category order are still being mocked there; this page packs adjacent categories greedily in the order the situation's list first names them. The text rows here use the same categories and labels.
  • The setting is named “Show quick command icons” and is on by default. Off: no icon strip, and All Commands' submenus sit at the menu root.

Found in the code while drawing (static reads, main at 03138ce7c)

  • Two catalog entries are in no All Commands group. Make left / right closed traffic and Proceed on course are referenced only by their catalog entries (MenuCatalog.cs:400-427), the VFR-departing default list (QuickCommandDefaults.cs:223-227) and their glyphs (QuickCommandGlyphs.cs:165-173): today they are reachable only from that one situation's quick commands, or by typing. Decision 1 gives them a home.
  • Warp… has a verb. It sends WARP {frd} {h} {a} {s} (MenuCatalog.cs:1111) and Delete sends DEL (:142), so the rows with no command of their own are Command…, Note…, Edit flight plan, Favorites and the submenu headers (decision 4.2).
  • Some icons have no text twin. On a radar point with an airborne aircraft, Direct to, Hold (left), Hold (right) and Warp here are strip icons only; the text rows are Fly heading and Append direct to (AircraftMenuBuilder.cs:199-211, :237-244). A delayed spawn's Release (HFR) and Check release window are icons only too (:337-350). Hiding those strips (decision 6.2a) needs text rows for them.
  • A new preference key has to choose a bundle side. SettingsBundlePreferencesTests fails until a key is in BundledRules or in UnbundledKeys with a reason (UserPreferences.Bundle.cs:160-161), and the quick-command lists themselves travel as their own file, *.yaat-quickcommands.json, not in the settings bundle (:168). Decision 6.1.
  • The menu sends canonical verbs, the command bar completes the user's. CommandScheme.PrimaryVerb is a scheme's first alias (CommandScheme.cs:7) and completion inserts it (CommandInputController.cs:1193); Fly heading's aliases are FH, H (CommandRegistry.cs:172), Cleared to land's CLAND, CL, FS (:484). Decision 4.3.
  • No catalog entry carries its verb. MenuCatalogEntry is (Id, Label, DefaultFlightRules, IsApplicable, Build); a verb is readable only from a built leaf's MenuCommandText, which flyouts, input leaves and host leaves do not set. Every alias drawn here is a new per-entry datum. A runway leaf's label carries the runway (“Cleared to land 28L”) while it sends the bare verb (CLAND, MenuCatalog.cs:596-597), so the alias column shows the verb, not the label's runway.
  • A one-icon category cannot carry its label in a shared row. Under 1028's packing, N123AB's lone Squawk assigned code icon shares a row with Runway, and “Track and coordination” over one 42 px cell ellipsizes to “TR…” (drawn so). A question for the 1028 packing mock, not this one.
  • YAAT-762 has landed: StripCapacity is 15, three rows of five (QuickCommandGlyphs.cs:57), and Squawk normal / Squawk assigned code lead most lists. 1028 removes the cap; the Quick commands section's intro still says “The first fifteen commands with an icon form the icon strip” (QuickCommandsSection.axaml:22).

YAAT-1028 · context-menu quick commands · mock for the owner's decisions

Every quick-command icon, grouped by category

Owner request: “No limit on the amount of quick command icons that are shown in a context menu, but maybe they should be organized into categories with small separators?” Today the strip holds the first ten glyph-bearing entries of the situation's list, two rows of five, and every glyph entry past the tenth drops to a text row. This page draws the strip with no cap, its icons grouped by category, four ways, against today's menu.

Each artboard is one aircraft situation, its lanes side by side at the menu's real width: the title, the state line (point at an icon and it names the command there, as the built strip does), the strip, and the rows below it. The pointer arrow marks where the right-click landed: the menu opens with its top-left corner there. Under each menu a measured line gives the menu's height, the icon farthest from the pointer (dashed blue ring) and every one-icon group (amber underline). The switches above the artboards re-draw every lane for decisions 2 to 5 and 7.

Glyphs, families, colours, sizes and the situations' lists are the built ones. Every entry of a list is drawn, as Settings' preview draws it: on a real aircraft the visibility rules hide some (Land on a fixed-wing, Cancel takeoff clearance with no clearance), so real menus are often shorter. Callsigns and state lines are illustrative.

The strip as built

  • Cap and split. QuickCommandGlyphs.StripCapacity is 10; Split puts the first ten glyph-bearing entries in list order in the strip and every other entry, a glyph-bearing one past the tenth included, in the text rows below it. QuickCommandStrip.Rows lays the cells out in two rows of RowLength = 5, an empty second row hidden; Settings' preview lays out through the same Rows and GlyphCell.
  • Cells. A 40 px cell (42 px with the button's border), a 32 px glyph drawn on a 24 px view box at stroke 1.9 in its family's colour, 6 px apart, on a #1F2226 well; a corner notch (M6 0V6H0z, #9AA3AD) on a button that opens a flyout.
  • Families. Five, in QuickCommandGlyphFamily order: Tower amber #FFC062, Ground teal #6EE0CE, Flight blue #A8CAFF, Pattern violet #DDBDFF, Scope and sim grey #DCE2E8.
  • Header line. The state line under the title names the icon under the pointer or focus (QuickCommandLabelLine): its name, then — COMMAND for one fixed command or › for a flyout.
  • Release icons lead. Release (HFR) and Check release window, when they apply, go first in the strip whatever the list (AircraftMenuBuilder.LeadWithRelease), and an icon they push past the tenth becomes the first text row.

Found while drawing (static reads, not run)

  • The cap is still ten. YAAT-1028 says YAAT-762 raises it to 15; QuickCommandGlyphs.cs:57 still reads StripCapacity = 10 and Rows still builds two rows, so today's lanes are drawn at ten.
  • There is no coordination family. The issue names six families (“… scope and sim, coordination”); the code has five, and Release (HFR) and Check release window are ScopeAndSim (QuickCommandGlyphs.cs:188-189).
  • Family is not the same as job. Cleared for the option is drawn violet in the Pattern family (:179), not amber with the other tower clearances; Report traffic in sight, Report field in sight, At N-mile final and At fix are amber Tower glyphs (:116-119). Grouping by family moves them with their colour.
  • Two default lists already overflow. Pattern (11) and Holding (11) hold more glyph entries than the strip shows, so a helicopter in the pattern gets Land as a text row today; a release-window aircraft in the Taxiing list (10) pushes Land out the same way.
  • Six fits the menu as it is. Six 42 px buttons 6 px apart are 282 px, exactly the 290 px menu less its 4 px strip padding each side, so a six-wide row would not widen today's menu (decision 5).
  • Settings draws a divider after the tenth row (docs/client-context-menus.md, “Strip mark and preview”); with no cap it has nothing to mark.

YAAT-2212: how should the Ground View draw an airport it has no ground map for?

An airport first named mid-session has no ground layout, so the Ground View draws only its runways from navdata (both thresholds and the width), for display only: no taxiways, no ground interaction. It is there so a user can watch an aircraft land on or depart from that runway.

Each lane shows SFO (28L/10R, 28R/10L, 1L/19R, 1R/19L) drawn that way. UAL1532 is rolling out on 28R after landing and ASA331 is on its take-off roll on 1R. Aircraft silhouettes, datablocks, colours and the weather line are the Ground View's defaults (GroundColorScheme, GroundRenderer).

A. The normal runway drawing, nothing else

The runways as the Ground View draws them today (DrawRunways): fill, outline, centreline and a midpoint label on a dark box. At this zoom the renderer drops the 1L/19R label because it would overlap another one, as it does today. The view gives no sign that the ground map is missing.

B. Option A plus a small corner note

The same drawing, with a quiet note in the bottom-right corner (“No ground map — runways only”) so nobody looks for missing taxiways.

C. Lighter outlines with end labels, plus the note

Each runway as an unfilled outline with a label at each end (28R, 10L, …) instead of one in the middle, and the same corner note. It looks like a sketch, not a full ground map.

The toolbar row is the Ground View’s own filter bar, unchanged in every lane. SFO threshold positions are close approximations, not the navdata values, and are drawn north-up at the zoom the view uses when it fits the airport.

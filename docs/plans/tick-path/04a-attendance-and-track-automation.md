# Tick-path step 4 (first slice): attendance as a recorded input, then the track-automation bodies cross into Yaat.Sim

## Context

`docs/plans/MAIN.md` → current focus is the tick-path programme, step 4 (relocation), and its first item is
**attendance as a recorded input** (`docs/plans/tick-path/04-relocation.md`, README: "it unblocks the CST auto-accept
finding and retires the `ProcessAutoAccept` family the step-5 residual is made of").

**The problem.** CRC attendance lives in yaat-server's process-wide `PositionRegistry` (`Data/PositionRegistry.cs`),
keyed by connection id and filtered by room id. Three tick-reachable bodies in `TickProcessor.cs` read it —
`ProcessDelayedHandoffs` (`:1050`, the consolidation-owner check), `ProcessPointoutAutoAck` (`:1189`),
`ProcessAutoAccept` (`:1274`) — plus the router's one query `IActionHost.IsPositionAttended` (the `Consolidate` arm's
descendant transfer and the `Track` arm's `ConsolidationRedirect`). A temp reconstruction room
(`RoomEngine.CreateTempReplayEngine`, room id `snapshot-gen-{guid}`: bundle export, the oracle's reconstruct leg) attends
nobody; a same-room rewind (`RecordingManager.RewindAsync` / `RewindFromSnapshotAsync`) reads **today's** sockets at every
historical second. Either way the reconstruction auto-accepts handoffs and auto-acks point-outs the live session left
pending for a human, or vice versa. ADR 0003 and `CONTEXT.md` already fix the answer: *live, attendance derives from
connections; everywhere else it is a recorded input.* No existing test registers a CRC client and then rewinds
(`RewindAutoTrackHandoffTests` is the #188 pin with an empty registry), and no oracle fixture attends anyone.

**Decisions taken with the user 2026-09-06** (AskUserQuestion): scope = A + B + C below; the live server derives and
records at the head of each live second; one record carries the full set of attended position ids; B and C are
verbatim moves (the aviation findings — §5-4-7 point-out inversion, the 3 s solo floor, CST suppression — land
afterwards as their own named decisions).

**Discipline (tick-path README).** Predict the baseline changes before `YAAT_ORACLE_REBASELINE=1`; an unpredicted
`Added`/`Removed` stops the work; corpus triage per ADR 0004 (over-broad assertion → fix the test; genuine desync →
delete the recording; unexpected cause → stop); TDD red-first; green cross-repo (`pwsh tools/test-all.ps1`) before
every commit; each sub-commit records predicted-vs-got in `04-relocation.md`.

Facts that shape the design (verified this session):
- `RunProfile.RunsControllerAi => Kind != Replay`, so `RoomAiStaffing`'s registry reads never run during reconstruction — not a divergence source; it stays on the registry.
- Both rewinds already `Clear()` the room-owned `PositionSelections` by hand because it outlives the engine. Attendance will be **engine-owned** (a fresh engine starts empty; the snapshot + the log rebuild it), so no such hand-clearing.
- A rewind leaves the room in tape playback until `TakeControl`; `LeavePlayback` also fires at end-of-tape (`RoomTickLoopService:179`) and on session restore.
- `TrackOwner.MatchesPosition`, `ArtccConfigResolver.ResolvePosition(config, positionId)` / `GetTcpForPosition`, `GetStarsConfigForFacility`, `ConsolidationEngine.GetConsolidationOwner(…, isAttended, overrides)`, `ScratchpadRuleEngine`, `FieldElevationResolver`, `TrackEngine.HandleAcknowledge / MarkPreviousOwnerRetained / MarkRecentHandoffAccepted` are all already in Yaat.Sim — the moved bodies need nothing from the server but `PositionRegistry`.
- The Sim engine's own scenario load (`SimulationEngine.Scenario.cs:65-74`) never applies autotrack conditions; only the server's `PopulateRoom` does (`ScenarioLifecycleService:822/831`), and the generator-spawn autotrack runs only in the live consumer `TickProcessor.HandlePrePhysicsResult:98-114`.
- Terminal lines the moved bodies broadcast today (`[AutoAccept] …`, `[AutoAck] …`, `[AutoTrack] …`) are emitted inline; the engine's `TerminalEntries` drain sits in pre-physics only, so post-physics entries need a second drain step to reach the room the same second.

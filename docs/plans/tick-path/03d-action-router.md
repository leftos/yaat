Part of [tick-path unification](./README.md). 3d-0 … 3d-5b-1 shipped 2026-09-05; 3d-5b-2 is built (awaiting commit), 3d-5b-3 next; 3d-6 is the docs pass.

- [ ] **3d — the action router (steer 2026-09-05: "incorporate the replay-fidelity work into the tick plan").** The action-path twin of 3c: a recorded controller action is routed by *three* independent parse-and-decide chains — live `RoomEngine.SendCommandAsync` (~37 arms), Sim replay `SimulationEngine.ReplayCommand`, server reconstruction `RecordingManager.ReplayCommand` — and the tick oracle cannot see any disagreement between them by construction. The 2026-09-05 audit found the 2026-09-04 flight-plan skip arm was one of a class: **`SQALL`/`SNALL`/`SSALL`, `TAXIALL`, `TDLSOPS`, `ASDXALERTS`, `ADD` silently no-op on every replay and bundle export** (global commands recorded with an empty callsign, dropped by the appliers' aircraft-exists guard; `ADD` also draws `World.Rng` live and records no spawn, desyncing the RNG from then on); **server reconstruction ignores `ReactionDelaySeconds`** (every bundle snapshot reacts at the issue second) and never rebuilds `SoloTrainingEvaluator` after `RewindAsync` resets it; two track tables (`TrackCommandHandler` live/reconstruct vs `TrackEngine.Dispatch` Sim replay) and two identity resolvers with opposite AI-branch precedence; typed `FP`/`DA`/`RMK`/`APT` record no command text while the CRC path records both; `CFR` is never recorded. Plus live mutations that never reach the log at all: CRC-console CONS/DECON (`RecordAndDispatch` refuses `ConsolidateCommand`), per-TCP shared STARS state, clearances/hold annotations, Request Strip (both entry points), ASDE-X/SAID temp data. Design and evidence: the session plan file → promoted to ADR 0007 (written at 3d-6) at 3d-6. Decisions: scope = router + the unrecorded CRC mutations (attendance / wall-clock timestamps / strip+TDLS snapshot coverage stay in step 4 below); full post-dispatch mirror on every run kind (read-backs are sim state, the host decides broadcast); rejected commands are recorded and flagged. ## 3d-5b — the Class B records: plan (2026-09-05)

**Goal.** Every live mutation that reaches sim or room state through a CRC handler without a record — the Class B census of the 3d design — is recorded at its handler and re-applied through the router on every run kind, so a rewind or bundle export reproduces it. Decisions taken with the user 2026-09-05: (1) the CRC-console consolidate/deconsolidate entries go through the router as **text** (one Sim body — the CRC form gains the sender's consolidated-descendant transfer and the attendance check, exactly like typed `CONS`; the design's `RecordedConsolidationChange` is dropped); (2) the ERAM keyboard entries record **one `RecordedEramEntry(Callsign, Entry, IdentityCode)`** applied by a new Sim `EramEntryEngine` that the live handler also calls — one body, readable in bug-bundle history; (3) a list-qualified `RDTXT` is **`RDTXT /{listId} {text}`** (a leading `/token` is the list id; a message never starts with a slash).

**Deviation from the 3d design, to be stated in ADR 0007 beside assignments / `TdlsDumped`:** B5 surface temp data (drawn areas, labels, presets) is **not** recorded. It is facility furniture — `FacilityTempDataStore` persists every edit across rooms and restarts and seeds it into the next room — so a rewind must not un-draw what the store still holds. The one room-only part, the ASDE-X **safety-logic configuration** (runway closures the alert tick reads), *is* recorded.

**Oracle prediction for all three sub-commits:** the twelve baselines byte-identical — the `actions` script has no CRC coordination, console consolidation, position sync or ERAM step. Any `Removed`/`Added` stops the work.

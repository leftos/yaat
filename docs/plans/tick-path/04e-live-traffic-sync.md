# 04e — `LiveTrafficSync` becomes a Sim step over a feed port

The last step-4 body in `IHostSteps` (`src/Yaat.Sim/Simulation/Spine/IHostSteps.cs`). Its doc comment already names the target: delete the member and turn the `SpineOrder.PrePhysics` entry (`Spine/SpineOrder.cs`, last in pre-physics) from `SpineStep.Host` into `SpineStep.Sim`. Unlike entries A–I in [04-relocation.md](./04-relocation.md), the input is not Sim-owned state: it is the server's external SWIM feed. So the crossing is a dependency inversion (a feed port the Sim owns and the server implements), not a state migration.

## What it is today

- Live and reconstruction: `RoomHost.LiveTrafficSync` (yaat-server `Simulation/RoomHost.cs`) → `TickProcessor.SyncLiveTraffic` → `ShadowTrafficSync.Sync(room)` (yaat-server `LiveTraffic/ShadowTrafficSync.cs`). `BareHost` and `ReplayHost` bodies are empty.
- `Sync` does, in order: early-return and tear down shadows when the scenario has `LiveTrafficEnabled=false`; skip when broadcasts are suppressed or in playback (recorded samples own the world then); rebuild the cached `RoomLiveTrafficScope` (needs `ArtccConfigService`); resolve DVR replay (`TryStartReplay`/`Seek`); compute the wall-clock ↔ sim-second anchor (`IsContinuous`/`Anchor`, real `TimeProvider`); query `LiveTrafficStore` (or the room's `RoomLiveTrafficReplay`); per track apply the removal-window and filter gates and `ApplyTrack` (spawn vs refresh, callsign collision with a simulated aircraft) → `sim.ApplyLiveTrafficSample`; then `RemoveAbsentShadows`, three tiers (explicit feed-lifecycle end → out of scope 15 s → silence backstop per source) → `Remove` → `sim.RemoveLiveTraffic` plus assignments, change tracker and both broadcasters.
- Already Sim: `AircraftLiveTraffic`, `LiveTrafficKinematics.Apply`/`Resync`, `LiveTrafficFilterMatcher.Matches`, and `SimulationEngine.LiveTraffic.cs`'s `ApplyLiveTrafficSample` / `RemoveLiveTraffic` and their replay twins `ApplyRecordedLiveTrafficSample` / `ApplyRecordedLiveTrafficRemoval`, reached through `ApplyPreTickRecordedActions` on every non-live run kind. Replay, reconstruction and bare runs already reproduce shadow motion byte-for-byte from the recorded action log; what is host-side is only the live *decision*: which track becomes a sample this second and which shadow ages out.
- `RoomLiveTrafficState` (yaat-server, room-held, in no snapshot): `Scope`/`Filter`/`ScopeKey` (cache), `AnchorWallUtc`/`AnchorElapsedSeconds`/`LastSyncWallUtc`, `Replay` (DVR), `Suppressed` (the `DEL`-hidden set; `IActionHost.OnLiveTrafficHidden` writes it from Sim), `CollisionWarned`.

## Decisions (user 2026-09-24)

1. **Shape: a Sim step over a query port.** The server implements a feed port that answers "what is in scope this second" with samples already on sim time. `Yaat.Sim` owns spawn vs refresh, the collision check, the filter gate and the three removal tiers, reading engine-held timestamps (`AircraftLiveTraffic.AppliedAtSimSeconds`). Rejected: a verdict port (the server decides spawn/refresh/remove and the Sim only applies) — the host would still decide a simulation-affecting step, ADR 0001's forbidden residue.
2. **The wall-clock ↔ sim anchor stays in the server.** The port's samples carry `observedAtSim` already converted; no Sim step takes a wall-clock reading (ADR 0003's boundary: wall clock → sim time once, at the host).
3. **`Suppressed` moves into snapshotted Sim scenario state** (`SimScenarioState`), which also closes the two Wave 8 suppression residuals in [`MAIN.md`](../MAIN.md) (a planned-restart restore drops it; a rewind re-raises a skipped `DEL` after an off/on toggle had cleared it) — that line moves here.
4. **DVR replay is the server's concern.** The port queries whichever store is active; the Sim sees one interface.

## Steps

**Steps 1–3 shipped 2026-09-24** (one implementer brief): the port is `ILiveTrafficFeedPort` — `BeginSecond()` → `LiveTrafficFeedSecond(Syncs, ClearShadows, Tracks)` (the re-acquire gap stays in the server's feed, which writes the "rejoined" line), `ShadowStatus(callsign)` → `LiveTrafficShadowStatus { Absent, Ended, FilteredOut, OutOfScope, Present }`, `EndSecond()` (runs `replay.Advance` after the lookups) — hung on `IHostConsumers.LiveTrafficFeed`; `SimulationEngine.TickLiveTrafficSync` holds spawn vs refresh, the collision check, the filter and suppression gates and the three tiers; five `IHostConsumers.OnLiveTraffic*` consumers carry the outcomes; `IHostSteps` has no simulation-affecting member left. Oracle: twelve baselines byte-identical, as predicted. Corrections to this plan: `LiveTrafficFilterMatcher`, `LiveTrack` and `LiveTrafficAircraftFactory` are server types, not Sim ones — the port evaluates the filter and passes `MatchesFilter` per track, and the spawn template is a lazy `Func<AircraftSnapshotDto>`; the silence horizon is already Sim (`LiveTrafficKinematics.RemovalAfterSeconds`) and does not cross the port; every inert case (no scenario, broadcasts suppressed, playback, replay not ready) is the port's answer, so the step never asks whether it is live. Only step 4 remains.

1. **The port.** `src/Yaat.Sim/LiveTraffic/ILiveTrafficFeedPort.cs`: a per-second query returning the scoped track set as `(callsign, LiveTrafficSample, spawn template, feed-lifecycle-ended flag, in-scope flag)` and each source's silence horizon — the exact member list is fixed by reading `ApplyTrack` and `RemoveAbsentShadows` so every input the tiers read comes through it. `BareHost` and `ReplayHost` supply an empty port (today's behaviour exactly). Where the port lives on the host: ADR 0005 — on the host, never on `RunProfile`; a step asks the port, never "am I live?".
2. **`SimulationEngine.TickLiveTrafficSync(port, IHostConsumers)`** in `SimulationEngine.LiveTraffic.cs` (ADR 0006: extend the existing partial): `ApplyTrack`'s spawn/refresh branch, the collision check, the filter gate and the three removal tiers move verbatim, calling the existing `ApplyLiveTrafficSample` / `RemoveLiveTraffic` (ADR 0007: one action router, no second recording path). Spawn, removal, collision and filtered-out results reach the host through consumers (the `OnAsdexAlertsChanged` shape, entry I), so `RoomHost` keeps `afterSpawn`, `AircraftAssignments`, `ChangeTracker`, both broadcasters and the terminal lines. `SpineOrder` entry → `SpineStep.Sim`; `IHostSteps.LiveTrafficSync` and `TickProcessor.SyncLiveTraffic` deleted. Proving: `LiveTrafficSyncStepTests` (Sim) over a fake port on a bare engine — spawn, refresh, each removal tier, filter exclusion, collision with a simulated aircraft — red first against the empty `BareHost` body.
3. **The server implements the port.** `ShadowTrafficSync` shrinks to scope and anchor bookkeeping and building the query from `LiveTrafficStore` / `RoomLiveTrafficReplay`. Proving: `ShadowOwnershipTests`, `ShadowScratchpadTests`, `ShadowDisplayStateTests` unchanged; new server tests pin the port's answers against `LiveTrafficStore` fixtures. Oracle: no fixture drives live traffic, so predict all twelve baselines byte-identical before running.
4. **`Suppressed` into `SimScenarioState`** (snapshot schema bump through `SnapshotSchemaMigrator`): `IActionHost.OnLiveTrafficHidden` goes away when nothing host-side still reads the set. Proving: `LiveTrafficRemovalSuppressionTests` unchanged; a snapshot round-trip test; red-first pins for the two residuals (a restore keeps a `DEL`'d shadow hidden; `DEL`, toggle live traffic off and on, rewind past the `DEL` → the shadow stays visible).
5. **Review.** `csharp-reviewer` on each commit; `aviation-sim-expert` only if a removal tier or the coast timing changes behaviour (ADR 0002: a semantic difference is a named decision, not an ordering fix). Docs: `docs/tick-loop.md` (Hosts, spine table), `docs/live-traffic.md`, yaat-server `docs/architecture.md`, the `IHostSteps` list in [04-relocation.md](./04-relocation.md) and [README.md](./README.md).

## Done when

`IHostSteps` has no step-4 member; `SpineOrder` has no `SpineStep.Host` entry for live traffic; a `DEL`'d shadow stays hidden across a planned restart and across the toggle-then-rewind case; twelve oracle baselines empty.

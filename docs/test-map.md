# Test Map — where a behaviour is pinned, and where a new test belongs

> The almanac of **classes of test**, keyed by subsystem the way [`architecture.md`](./architecture.md)'s Task Index is keyed. It answers two questions before you write a test: *is this behaviour already pinned somewhere?* and *which shape and folder does the new test take?* It is deliberately not a per-file listing (1,100+ test files, 8,000+ test methods — a listing rots on contact and is derivable with `rg`); each row names a shape, two to four representative files, what the shape pins, the harness it needs, and the placement rule. Harness mechanics (singleton races, `TestVnasData`, the `ModuleInit`s, the 30-second timeout) live in [`test-harness.md`](./test-harness.md); the replay-driven bug workflow in [`e2e-tdd-issue-debugging.md`](./e2e-tdd-issue-debugging.md).

Counts below are approximate `[Fact]`/`[Theory]` totals at 2026-09-10 and exist only to show where the weight is.

## 1. Which project

| Project | Owns | Runs under | Put a test here when… |
|---|---|---|---|
| `tests/Yaat.Sim.Tests` (~7,000 methods) | everything in `Yaat.Sim`: commands, phases, physics, ground stack, navdata, scenarios, pilot AI, speech rules, controller AI, snapshots, the tick spine and action router | `ModuleInit` pins NavData + CIFP as hard preconditions, `GroundNavigator.ThrowOnOrbit = true` | the behaviour is simulation logic — even if a client or server feature exposed it. Sim tests never need a server or a window |
| `tests/Yaat.Client.Tests` | pure view-model / service / parser logic of the desktop client, plus minimal-Avalonia control and geometry tests | `ModuleInit` redirects `YAAT_APPDATA_DIR` to a per-process temp | the class under test is a pure function of a VM, service or model, or a single control's binding — `MainWindow`/`MainViewModel` wiring would be overkill (`Views/HeadlessTestApp.cs` is a *minimal* `Application`, not the real `App`) |

| `yaat-server/tests/Yaat.Server.Tests` (313 files) | rooms, hubs, CRC wire and STARS/ERAM command dispatch, `DtoConverter`, replay/reconstruction equivalence, the tick oracle, soak, live-traffic/SWIM, auth | own `Resources/` fixtures + `NavigationDatabase.ForTesting()` by default; `RoomEngineTestHarness.ResolveRealNavDb()` opts into yaat's real navdata (sibling-repo path, silent skip when absent) | the behaviour needs a room, a hub, a CRC client, or a run-kind comparison. Two DTO shapes are asserted from both sides of the wire on purpose (`RoomMembershipWireShapeTests` in Client.Tests and Server.Tests; `GroundViewModel*Tests` vs `DtoConverterGroundLayoutTests`): editing that DTO means touching both.

## 2. Inside `Yaat.Sim.Tests` — root, `Simulation/`, or a subsystem folder

The rule the tree actually follows (nothing documents it elsewhere):

- **Needs a `SimulationEngine`** — `Replay(...)`, `RunSecond`, `SendCommand` across ticks, several aircraft, the action router → **`Simulation/`**. Flat there for bug pins (`IssueNNN*`, `S2Oak*`, `Oak*`/`Sfo*`/`Mia*`-prefixed, `*E2ETests`); a subfolder when a subsystem accumulated its own bare-engine `*StepTests` (`Simulation/{Actions,Asdex,Bookmarks,Coordination,Eram,Strips,TowerLists,Tdls,Oracle,Snapshots,GroundTaxi}/`).
- **Hand-built `AircraftState` / `PhaseContext` / a parser call, no engine** → the **root** (physics, phases, parsers, weather, conflict detection, command handlers) — *unless* a subsystem folder already exists for it (`Commands/`, `Pathfinding/`, `Fillet/`, `Phases/`, `Pilot/`, `Speech/`, `Scenarios/`, `ControllerAi/`, `LiveTraffic/`, `Data/`, `Training/`, `Artcc/`, `Asdex/`, `Acceptance/`, `PathfinderGrid/`, `Soak/`). "Does a folder exist" is the signal, not file count: `Data/` has 9 files, weather and conflict detection have dozens at the root.
- Issue-numbered and descriptive bug-pin names coexist at both root and `Simulation/`; the number is not what decides placement, the engine is. `IssueNNN` names are for a reported bug; a class that pins a rule gets a rule name.
- Folder and namespace disagree in places (`Data/*` declares `Yaat.Sim.Tests`; `Phases/Tower/LandingPhaseCompletionStampTests` declares `Yaat.Sim.Tests.LandingPhaseTests`) — search by folder, not namespace.

Heavy work is gated, not skipped: `[Trait("Category", "Nightly")]` (the per-spot taxi-coverage grids in `Simulation/GroundTaxi/TaxiCoverage{Oak,Sfo}GridTests`) and `[Trait("Category", "PathfinderGrid")]` (`PathfinderGrid/StateAwarePruningNecessityTests` **and** `Pathfinding/Req1MembershipArcSweepTests`) are excluded by `tools/test-all.ps1` unless `-Full`. `Acceptance/*` is not gated but runs in a `DisableParallelization` collection because it writes `TickRecorder` files. `ControllerAi/ControllerAiDeterminismTests` (900 sim-seconds) and `GroundBrainE2ETests` are the heaviest always-on tests.

- `TestData/*.geojson` (16 airports) — `TestAirportGroundData.GetLayout("OAK")`; runway width comes from navdata, so never hard-code node ids. Client.Tests links `oak`/`sfo` from here.
- `TestData/NavData.dat`, `FAACIFP18.gz` + manifests — the hard preconditions; refresh with `tools/refresh-navdata.py`.
- `TestData/artcc-zoa-snapshot.json` — `TestArtccConfig.LoadZoa()`; `tools/refresh-artcc-snapshot.py`.
- `TestData/recording-routing-census.json` — owned by `RecordingCorpusRoutingCensusTests`; every new recording fixture must be registered (`YAAT_ROUTING_CENSUS_REGENERATE=1`), and the diff must only add.
- `docs/tick-oracle/*.baseline.json` (yaat-server) — owned by `TickOracleTests`; `YAAT_ORACLE_REBASELINE=1`; a Note in a baseline is a hypothesis until a retirement test confirms it.
- `docs/crc-wire/messaging-contract.json` (yaat-server) — regenerated by `tools/CrcWireDump` on each CRC release.
- `TestData/Scenarios/{ARTCC}/` — not committed; populated by yaat-server's `validate-all-scenarios.py`; absent means `VnasScenarioParseTests` silently passes.
- yaat-server `Resources/` — its own scenarios, ZOA config and OAK GeoJSON; `LiveTraffic/Swim/Fixtures/*.xml` are real SCDS captures.

## 6. Known overlaps worth a maintainer decision

- `Helpers/ParsedCommandDummyFactory` and `Helpers/ParsedCommandDummies` both reflect over every `ParsedCommand` subtype to mint placeholders — one for the describer/classify sweeps, one for the action-routing sweeps. Same mechanism twice.
- `Fillet/GroundArcSpeedProfileTests` (the generator's profile) and root `GroundNavigatorArcSpeedProfileTests` (the navigator applying it) are complementary, not duplicates; the split is generator vs navigator.
- Taxi coverage runs at three tiers over one `TaxiCoverageData` (`Acceptance/` smoke, curated `TaxiCoverage{Apt}Tests`, `Nightly` grids). The tier rule lives in the grid test's doc comment and in §4's ground-pathfinder row; nowhere else.
- `Fillet/FilletComparisonTests` (clone fidelity) and `Fillet/FilletComparisonGateTests` (structural gates) invite confusion by name only.

When you add a class of test this map does not have, add the row — the map is only useful while it is complete.
